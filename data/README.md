# Data layout

The repository ships the **curated Telugu → ISL mapping** but not the large
frame corpus, audio recordings or GIFs.

**Related documents:** [README](../README.md) · [Setup guide](../docs/SETUP.md) · [Architecture](../docs/ARCHITECTURE.md) · [Paper notes](../docs/PAPER_NOTES.md)

Put them here:

```text
data/
├── mappings/
│   ├── telugu_to_isl.json              # shipped: 214 Telugu words -> ISL glosses
│   ├── telugu_to_isl_corpus.json       # generated by --mode prepare
│   ├── isl_corpus_signs.json           # generated by --mode prepare
│   └── isl_corpus_index.json           # generated by --mode prepare
├── audio/                              # optional: Telugu speech for training
│   ├── female/
│   │   ├── line_index_female.tsv
│   │   └── *.wav
│   └── male/
│       ├── line_index_male.tsv
│       └── *.wav
├── gifs/                               # optional: fallback GIF library
│   ├── alphabets/
│   ├── numbers/
│   └── words/
└── ISL_Corpus/
    └── Frames_Word_Level/
        ├── HELLO_HI/
        │   ├── 001.jpg
        │   ├── 002.jpg
        │   └── ...
        ├── THANK/
        └── ...
```

## Naming rules

* A **sign directory name is the gloss** used in the mapping file
  (`HELLO_HI`, `THANK`, `SCHOOL`). Matching is case-insensitive and `-` is
  normalised to `_`.
* Frames are sorted by the first number in the filename, so zero-padded names
  such as `001.jpg`, `002.jpg` are recommended.
* Supported frame formats: `.jpg`, `.jpeg`, `.png`.

## Where to get data

The frame corpus is not redistributed here. Any ISL word-level frame dataset
laid out as above works. The original paper used a manually collected GIF
library plus the Free Spoken Digit Dataset (FSDD); the runtime in this repo is
designed around a word-level ISL frame corpus.

For Telugu audio, OpenSLR Telugu speech corpora can be converted to the
`data/audio/<gender>/` layout with a `line_index_<gender>.tsv` transcript file
(`file_id<TAB>Telugu sentence`).

## Validate the corpus

```bash
python app.py --mode prepare
python app.py --mode info
```

If the corpus is missing, the app still runs and shows a text card for every
sign it cannot animate. That fallback is intentional: the translation is never
silently dropped.
