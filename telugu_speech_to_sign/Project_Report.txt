SYSTEM ARCHITECTURE & TECHNICAL REPORT
 Telugu Speech-to-Sign Language Translation Framework
 ====================================================

 1. SYSTEM ARCHITECTURE
 ----------------------
 The system follows a modular pipeline architecture designed to convert Telugu audio input into Indian Sign Language (ISL) animation sequences.

 High-Level Data Flow:
 Audio Input (Telugu) -> Speech Recognition (STT) -> Telugu Text -> NLP Translator -> Sign Sequence -> Corpus Animator -> Visual Output

 Core Components:

 1. Frontend GUI (gui/app.py):
    - Built with CustomTkinter for a modern, dark-mode interface.
    - Handles Audio Recording (PyAudio), File Uploads, and Text Input.
    - Visualizes the sign language output frame-by-frame.

 2. Speech Recognition Module (modules/audio_processor.py):
    - Engine: Google Speech Recognition API (via SpeechRecognition library).
    - Function: Converts variable-length Telugu audio into UTF-8 Telugu text.
    - Optimization: Calibrates for ambient noise before recording.

 3. NLP & Translation Module (modules/nlp_translator.py):
    - Core Logic: Hybrid Mapping + English Pivot Bridge.
    - (Step A) Direct Mapping: Checks 'telugu_to_isl.json' for direct Telugu-to-Sign matches (e.g., "నమస్కారం" -> "HELLO_HI").
    - (Step B) English Bridge (New): Uses 'deep-translator' (Google Translate API) to convert unrecognized Telugu words to English (e.g., "వెళ్తున్నాను" -> "Going").
    - (Step C) Fuzzy Matching: Matches English words to ISL signs using suffix stripping (e.g., "Going" -> "GO") and keyword matching.

 4. Animation Module (modules/isl_corpus_animator_enhanced.py):
    - Database: Uses the ISL CSOLT Corpus (3GB+ of image frames).
    - Logic: Retrieves frame sequences for mapped signs.
    - Fallback: If a sign video is missing, it displays the text to ensure information isn't lost.

 2. ALGORITHMS USED
 ------------------

 * Speech-to-Text (STT): Hidden Markov Models (HMM) and Deep Neural Networks (DNN) via Google's API for low-resource language (Telugu) recognition.

 * Natural Language Processing (NLP):
    - Tokenization: Splitting sentences into meaningful units.
    - Stemming/Suffix Stripping: Custom algorithm to map variations (e.g., "Running", "Ran") to root signs ("RUN").
    - Pivot Translation: Using English as a high-resource pivot language to bridge the gap between Telugu and ISL.

 * Image Sequence Processing:
    - Frame Caching: Pre-indexing 200+ ISL sign directories for sub-millisecond lookup latency.
    - FPS Synchronization: Controlling frame delay to match natural signing speed (approx. 20-30 FPS).

 * Deep Learning (Recognition - Optional):
    - ResNet + BiLSTM: Residual Neural Networks for spatial feature extraction combined with Bidirectional LSTMs for temporal sequence modeling.
    - Note: The current app flow focuses on Generation (Speech->Sign), utilizing the Corpus logic instead of this recognition model.

 4. WHY REMOVE TEMP FILES?
 -------------------------
 Files like 'temp_audio.wav', '__pycache__', and 'logs/' are transient. Removing them ensures:
 - Privacy: User recordings aren't stored permanently.
 - Space: Frees up disk space.
 - Cleanliness: Prevents conflicts with old cache data during code updates.

 6. PRESENTATION: SYSTEM ARCHITECTURE BREAKDOWN
 ----------------------------------------------
 (Use these points for your slides)

 Slide 1: The High-Level Flow
 - Input: User speaks into the microphone (Telugu).
 - Process:
   1. Google API converts Speech -> Text.
   2. NLP Engine translates Text -> Sign Labels.
   3. Animator looks up Sign Images from Database.
 - Output: Visual Sign Language Animation on Screen.

 Slide 2: The Translation Logic (The "Brain")
 - Problem: Not every Telugu word has a direct sign video.
 - Solution: "Hybrid Translation Engine"
   - Layer 1: Direct Mapping (Fastest). Checks if exact Telugu word exists in database.
   - Layer 2: English Bridge (Smartest). If no Telugu sign, translates to English (e.g. "Velthunnanu" -> "Going").
   - Layer 3: Fuzzy Match (Broadest). Matches "Going" to "GO", "Happily" to "HAPPY" to find the closest available sign.

 Slide 3: The Animation Engine
 - We use a "Corpus-Based" approach, not 3D avatars.
 - Benefit: Real human expressions (more natural).
 - Performance: Pre-indexed 100+ sign directories for instant playback without loading delays.
